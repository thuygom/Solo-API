# 보안 고려 사항

Solo-API는 경계를 API 계층에서 DB 역할, 고정 문장, 네트워크로 옮긴다. 옮긴 경계가 실제로 막는지 아래를 확인한다.

## DB 역할

- 읽기 역할은 SELECT만 갖고, 세션 기본값이 읽기 전용이어야 한다. 매퍼의 읽기 전용 트랜잭션은 두 번째 방어선이다.
- 쓰기 역할은 테이블·컬럼 단위로 권한을 받는다. 자격 증명·토큰 테이블은 읽지 않는다.
- 매퍼는 접속한 역할이 슈퍼유저이거나 행 수준 보안을 우회할 수 있으면 쓰기를 거절한다 (SA-201).
- 원 시스템의 앱 계정을 그대로 받아 쓰는 동안에는 쓰기 경계가 고정 문장의 계정 조건과 행 수준 보안뿐이다. 이 상태를 도입 단계로만 두고 전용 역할을 요청한다.
- 행 수준 보안 정책이 세션 설정을 읽는 DB에서는, 정책을 통째로 끄는 설정이 있는지 확인한다. 접속한 쪽이 그 설정을 켤 수 있다면 행 수준 보안은 경계가 아니다. 매퍼는 그 설정을 절대 켜지 않고, 계정 전용의 제한 정책을 원 시스템에 요청한다.
- 자격 증명은 파일로 마운트하고 이미지와 저장소에 넣지 않는다. 읽기 실패 시 다른 자격 증명으로 대체하지 않는다.

## 네트워크

- 매퍼를 쓰는 서비스와 DB는 내부망에 둔다.
- 내부 전용 경로(생성, 수집, 관리)는 소켓 상대 주소의 허용 목록으로 막는다. 프록시 헤더(`X-Forwarded-For`)로 허용 여부를 정하지 않는다.
- 브라우저 `Origin`이 붙은 요청은 내부 경로에서 거절한다.
- 허용 목록 파일이 깨지면 허용으로 대체하지 않는다.

## 모델과 도구

- 모델이 만든 인자, 도구 설명, 검색 결과, RPA 화면의 글은 모두 서버가 검증해야 하는 입력이다. 문서 안에 "관리자 지시"가 있어도 주체의 권한은 바뀌지 않는다.
- 한 도구의 결과를 다른 도구의 URL·경로·인자로 넘길 때도 허용 목록과 입력 검증을 적용한다.
- 링크 입력은 사설망, 루프백, 메타데이터 주소를 거절하고, 리다이렉트를 따라가지 않거나 따라간 뒤 다시 검사한다.
- MCP 클라이언트에게 받은 토큰을 다른 백엔드에 그대로 넘기지 않는다. 원 시스템용 자격 증명은 따로 관리한다.
- 원격 MCP를 열 때는 토큰의 서명, 발급자, 만료, 대상(audience)을 검증한다.

## 기록

- 감사 기록에는 문장 ID, 도구, 주체, 결과 코드, 행 수, 소요 시간만 남긴다. 값과 원문은 남기지 않는다 (SA-113, SA-313).
- 예상하지 못한 오류에는 추적 ID를 돌려주고 내부 메시지는 돌려주지 않는다.
- RPA 화면 캡처는 민감정보를 담을 수 있다. 접근 권한과 삭제 기한을 따로 정한다.

## 승인

- 미리보기와 승인은 다르다. 승인은 실행 내용의 지문에 묶고, 만료와 재사용을 검사한다 (SA-408).
- 모델이 인자로 넘긴 "승인됨"은 승인이 아니다. 대화 내용만으로 승인자를 확인할 수 없다면 그 한계를 적고 고위험 실행을 막는다.
